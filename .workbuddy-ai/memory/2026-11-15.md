
## Incremental stitching verification (26-target ARCore flow)
User spec: after each saved photograph, run REAL feature matching/stitching against
captured neighbours; per-image PASS/FAIL/PENDING with reasons + metrics; intermediate
stitched outputs; results UI; persistence; final panorama integration. Destination repo:
workspace IS the destination clone (origin=adaptive_360_capture_app.git, branch
feature/sitewise-arcore-capture-test at 9c5ba73; local commit e42bdb5 "joel" on top).

Implemented:
- `lib/features/capture/domain/stitch/incremental_stitch_models.dart` (pure): StitchStatus,
  ImageStitchRecord (matches/inliers/reproj/overlap/quality metrics + imageToken for
  retake invalidation), IntermediateStitch, StitchGroupState (idempotent addMember),
  FinalPanoramaRecord, StitchResultsDocument JSON.
- `domain/stitch/stitch_neighbor_planner.dart` (pure): same frustum-extent rule as
  StitchValidator; geodesic via unit directions; nearest-first cap 3. Layout facts:
  26 targets = 8/ring at 45° yaw (ids 1–8 middle, 9–16 upper +45, 17–24 lower −45),
  25 zenith, 26 nadir.
- `data/stitch/incremental_stitch_store.dart`: stitch_results/stitching_results.json
  (unique temp + rename, retry on Windows lock), stitched_outputs/stitch_NNN.jpg scan.
- `data/stitch/incremental_stitch_service.dart`: serialized queue (_chain), dedupe
  (settled results never re-run), retake invalidation via imageToken (capture time+path),
  dependent-reset, PENDING requeue on new saves, stale-job discard after mid-job retake,
  final-panorama begin/complete with failure attribution, `idle` future for tests.
  Registration thresholds: ≥20 good matches, ≥12 inliers, ≤8px mean reproj.
- `data/stitch/incremental_stitch_worker.dart`: real OpenCV in Isolate.run — imread,
  downscale 1024, ORB(3000)+BF-Hamming knn ratio 0.75, findHomography RANSAC 4px
  (Mat.fromVec(VecPoint2f)), metrics, quality gate (Laplacian var ≥30, brightness),
  merges: group (cv.Stitcher PANORAMA, work 1280) then pairwise fallback, temp+rename.
- Controller hook: optional `incrementalStitch` param; `unawaited(onCaptureSaved(record))`
  strictly after persist in _runCapture. Flow screen owns the service (station dir
  resolved lazily from record paths); review screen takes over onChanged; review gets
  StitchingResultsPanel; flow screen gets live StitchingStatusStrip overlay.
- Fixtures: tool/generate_stitch_fixtures.py (PIL, seeded) → test/fixtures/stitch/*.jpg
  (lap-var sharp ≈2600–4100, blurred ≈0.5).
- Tests: test/incremental_stitch_{models,neighbor_planner→stitch_neighbor_planner,
  service}_test.dart (fake worker, 12 scenarios), incremental_stitch_worker_test.dart
  (real OpenCV fixtures), integration_test/incremental_stitch_device_test.dart
  (on-device ARM OpenCV: synthesizes JPEGs via cv.randu+imencode).
- tool/verify_incremental_stitch.dart: pure-VM harness (dart --packages=
  .dart_tool/sphere_verify_package_config.json — now also maps path-1.9.1) — 17/17 PASS.

## 38-target projection/FOV/coverage fix (commit 16471a2 baseline)
Root cause: EquirectangularStitcher decoded frames at REDUCED_COLOR_4 (¼ scale, default
2048-wide output) but computed focal from `sourceImageHeight` (full-res) → focal 4× too
large in decoded pixel space → every frame's angular footprint collapsed → coverage
audit saw holes almost everywhere.

Fix:
- NEW `domain/sphere_intrinsics.dart` (pure): decodedProjection() — focal computed once
  on the uncropped source frame (lens property), scaled by decodedH/savedH (reduced
  decode), principal point = source centre − crop offsets, scaled. FOVs derived, never
  hard-coded. Null on invalid input, staged fallbacks (source→saved→decoded).
- NEW `data/jpeg_size.dart`: pure readJpegSize/EXIF parsing extracted from
  jpeg_normalizer (VM-testable); normalizer re-exports it.
- NormalizedJpeg + CaptureRecord + controller: cropOffsetX/Y recorded (default 0).
- stitcher: uses decodedProjection; writes coverage_map.jpg (red/yellow/blue/teal by
  hits) + coverage_report.json (single/double/triple %, uncovered %, largest gap,
  top-6 15°-cell uncovered regions, passed flag) BEFORE the 99.5% gate — failures are
  inspectable; panorama encoding via shared _encodeJpeg helper.
- sphere_target.dart: kSphereAssumedVerticalFovDeg now dart-define-overridable
  (--dart-define=sphereVerticalFovDeg=61, int degrees), documented ASSUMED 65 (26mm-equiv).
- tool/sphere_coverage_report.py: hfov derived from vfov+3:4 aspect; sensitivity table
  65→40°: 38-target passes ≥50° vfov (65°: 100.00/91.09/53.13 single/double/triple,
  88.1% redundancy), fails 45°/40°. 26-baseline only passes at 65°.
- tool/verify_sphere_projection.dart (pure VM harness): Tests A–E+G — 31/31 PASS;
  Dart coverage sim matches Python to 0.01%.
- Tests: test/sphere_intrinsics_test.dart (A,B,C pure), test/jpeg_size_test.dart (D),
  test/sphere_stitcher_projection_test.dart (F, real OpenCV: 38 fixtures → 2:1 panorama
  + coverage report; reduced/full decode agree; 12-frame failure keeps originals),
  test/fixtures/sphere/*.jpg (38 portrait 3:4, hue-coded, 3.7MB, regenerable via
  tool/generate_sphere_fixtures.py).
- flutter test on host still blocked by sandbox (reg.exe in dartcv4 native-assets
  probe; also breaks with C1083 float.h cascade). Harnesses: verify_sphere_geometry
  38/38, verify_incremental_stitch 17/17, verify_sphere_projection 31/31 — all green.
