# 2026-11-17

## 360 module backend — source review (read-only)

Question answered: "is the 360 backend Supabase only?" Answer: No — two separate backend tracks exist, and only one is wired into the app.

- **Supabase = the only cloud backend actually wired into the app.** `lib/main.dart:30` calls `SitewiseSupabase.ensureInitialised()`; `SitewiseServices.create()` builds `SupabasePanoramaGateway` + `PanoramaSyncService`. Flow: Supabase Auth (only IdP) → private Storage bucket `property-panoramas` → `pano_jobs` row (queued→processing→done/error) → signed URL for viewing. Config via `--dart-define=SITEWISE_SUPABASE_URL/SITEWISE_SUPABASE_KEY/SITEWISE_PANORAMA_BUCKET`.
- **Supabase-side server logic is SQL/migrations, not application code**: `supabase/migrations/2026111612*.sql` add four-role model, `pano_jobs.property_id` FK, private bucket, 4 Storage policies + 4 pano_jobs policies, `sitewise_can_manage_property()` and a role-change guard trigger. Plus `supabase/harness/` test standins. No Edge Functions present.
- **A second, standalone Python FastAPI backend exists** at `backend/src/sitesense` (`uvicorn sitesense.main:app --app-dir src`). It is NOT Supabase: own SQLite/Postgres DB via `SITESENSE_DATABASE_URL`, own Alembic tables `virtual_tours`/`virtual_tour_captures`, local filesystem capture storage, dev-only `X-User-Id` auth. Routes: `POST /api/v1/virtual-tours`, `POST /{id}/captures`, `POST /{id}/finalise`, `GET /{id}`. It stops at a stitch manifest; no stitcher worker implemented. No Supabase SDK/dependency anywhere in `backend/`.
- **The two tracks are not connected.** The Flutter client's HTTP seam (`virtual_tour_remote_data_source.dart`) targets `/api/v1/panoramas/stitch` and `/api/v1/virtual-tours/{tourId}/submit`, which do not exist in the FastAPI routes. It is gated behind `VIRTUAL_TOUR_API_BASE_URL`; when unset (default) the app uses `LocalVirtualTourRemoteDataSource`, which labels results `simulated`. Default stitching is on-device (OpenCV / `equirectangular_stitcher.dart`), not backend.

Bottom line: if "backend" means the cloud service the app talks to, it is Supabase-only — but the repo also contains an unrelated/unwired Python capture-ingestion API, and no server-side stitching/verification service exists.
