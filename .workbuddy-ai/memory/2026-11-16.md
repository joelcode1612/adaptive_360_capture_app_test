## Root causes traced to code

1. `equirectangular_stitcher.dart` writes uncovered pixels as 0 (`if (best <= 1e-4) continue;`),
   so any gap renders pure black.
2. Coverage gate is area-weighted by `cosLat[y]` (line ~412). A hole at the pole
   costs ~0.2–0.8% of sphere area, so it passes the 99.5% gate while being the most
   visible thing on screen.
3. `tool/sphere_coverage_report.py` models *ideal* aim only. At 65° VFOV: 100.00%
   single coverage but the worst frame-to-best-neighbour overlap (`min-nbr`) is only
   17.3%. `kSphereAlignmentToleranceDeg = 5` lets the auto-shutter fire 5° off target,
   which consumes that seam. Poles have 10° vertical overlap vs 30° between rings.
4. `kSphereAssumedVerticalFovDeg = 65` is an assumption; no calibration path exists
   (only a `--dart-define=sphereVerticalFovDeg` build override).
5. No gain/exposure compensation anywhere in the sphere stitcher — grep for
   gain/exposure/histogram returns nothing relevant. Causes the brightness steps.
6. Blend is nearest-frame with a 3% seam band only (`second > 0.97 * best`), so
   orientation error shows as a torn hard edge rather than a blend.

## Stitching upgrade (same day)

Facts that drove the design:
- `dartcv4 2.2.2` exposes **no `detail_` bindings** — no
  `ExposureCompensator`, `SeamFinder`, `MultiBandBlender`. `cv.Stitcher` has no
  setters to inject them either. So seam-aware compositing had to be built from
  exposed primitives (feather blending) rather than native `detail::`.
- Available and used: ORB, BFMatcher.knnMatch, findHomography(RANSAC),
  `decodedProjection`, imread reduced flags.
- `opencv_dart` is commented out of pubspec.yaml right now (host-test variant,
  toggled by `tool/host_test_pubspec.py off`). Restore with `... on` before
  building. This is why `flutter analyze` resolves nothing opencv-related.
- No `test/` directory exists in this working copy.

New files:
- `lib/features/sphere_capture/domain/sphere_registration.dart` — pure Dart
  rotation refinement (damped Gauss-Newton on reprojection error, finite-difference
  Jacobian), rejection rules, correction merging with shrinkage.
- `lib/features/sphere_capture/data/sphere_frame_registration.dart` — ORB
  descriptors once per frame, neighbour-only pairs from quaternions, RANSAC
  inliers cached per pair, sequential pass then Jacobi averaging.

Modified:
- `equirectangular_stitcher.dart` — registration before projection; gain+offset
  exposure; feather blending replaces the 3% nearest-frame rule; 2048/4096
  resolution policy with memory budget; per-stage timings in coverage_report.json.
- `stitch_job_runner.dart` — `refineRegistration` added to StitchWorkerArgs.
- `main.dart` — launcher label 26 → 38 targets.

Key design note to remember: refining **both** sides of a pair from priors
double-counts the relative error (each frame absorbs the full error in opposite
directions). Fixed by a sequential pass anchored to already-refined neighbours,
then a Jacobi averaging sweep.

schema so RLS policies can actually be **executed** on a local PostgreSQL.

Three findings from actually running it:
- **Admin could delete a `pano_jobs` row it could not read** — the read policy
  had no admin branch, so a legacy row with `property_id IS NULL` fell through
  `sitewise_can_manage_property(NULL)`. Fixed by adding the branch.
- A DELETE policy *filters* rather than raising, so "anonymous cannot delete"
  must be proven by row count on an object that exists — the first version of
  that assertion targeted a nonexistent path and proved nothing.
- `_solve3x3` returns `List<double>?` but the caller does `Vec3` math; the old
  `step.length` was a List element count (always 3), so the `1e-9` early-break
  never fired. Now converted via `Vec3.fromList` at the boundary — a latent bug,
  not just a type error.
